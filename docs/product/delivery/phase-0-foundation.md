## Deployment posture

The proven deployed baseline in `us-east-2` has synthetic staging and development on their
scale-to-zero JWT/Lambda paths with zero drift, enabled durable triggers, and environment-specific
reviewed gateway concurrency. Both terminal-acknowledgement releases are deployed after exact
historical drains. Fresh preference persistence, two-account isolation, 500/500 public requests,
25/25 durable workflows, aggregate Lambda/API/RDS/queue/alarm/privacy checks, empty work
boundaries, and zero drift pass in both environments. Staging and development cutover acceptance
are complete. Both environments have removed the legacy gateway/Temporal-worker ECS services,
task definitions, Cloud Map, VPC Link, and heartbeat path while retaining Single-AZ PostgreSQL
with backups/PITR and the on-demand migration boundary. Both provider keys are revoked; legacy
gateway/worker images, AWS containers, executable dependencies, operators, modes, and runbooks are
gone. Zero drift, runtime health, persistence, readiness, and two-account denial pass after
retirement. Repeated caller-account-scoped daily reads show stable attributable charges, healthy
budget/CUR controls, and zero ECS/Fargate cost. [D0-016](phase-0-serverless-runtime-migration.md) is
complete under [ADR-016](../../adr/016-scale-to-zero-application-runtime.md). Keep Fargate only for
explicitly on-demand migrations and later browser/ATS workloads.

Measured staging idle cost is still dominated by RDS and three interface endpoints. D0-017 now
implements [ADR-018](../../adr/018-disposable-prelaunch-staging-data-plane.md): development remains
continuously usable while staging moves through guarded active, quiesced, and dormant states. The
first complete lifecycle replay now passes dark recreation, migration through
`0003_retire_legacy_dispatch`, authenticated acceptance, fixed workload, AWS corroboration, and
separately approved return to dormancy. Staging again has no database, managed interface endpoint,
public route, enabled workflow trigger, queued work, or running ECS task. D0-017 is complete after
the product owner accepted direct resource absence and the full lifecycle replay as sufficient
evidence instead of waiting for a redundant billing-lag observation.
