# D3 generate-then-apply flow, 2026-10-20

Status: implemented and locally tested; not deployed; not accepted. Design:
[ADR-050](../../../adr/050-generate-then-apply-flow.md). Tasks D3-147 to D3-151.

## What changed

- Material reads go through authenticated BFF routes; the popup sign-in, the separate SPA use, the
  COOP popup exception and the "Disconnect material access" control are removed.
- `resumeGeneration` (not_requested, preparing, ready, failed, expired) is derived server-side; the
  UI follows it with a loading indicator, a failed message with retry and a one-click regenerate.
- Apply is the approval act; sensitive and empty direct-action answers stay explicit. Server hash
  binding, expiries and attempt guards are unchanged.
- Generated resumes are PDF only in OpenAPI, Documents, the native completion check and the
  extension contracts. `resume: uploaded` and `GET /applications/{id}/resume/uploaded` add the
  uploaded-resume fallback, default off (`UPLOADED_RESUME_ATTACHMENT_ENABLED`).
- The extension is armed by an identifiers-only `application-apply-intent.v1`.
