## Implemented path

Original resume task → fixed SDK-signed regional numeric Lambda RPC → AWS caller
identity verification → lazy Documents ledger with Applications/Jobs admission →
original scalar result. Generated content never enters this RPC.

The closed resume binding pins kind, original owner/application/generation/allocation/
epoch, exact task/deployment and original configuration digest. Its signing context
and request digest have distinct resume domains; cover-letter provider consent/work
is neither invented nor accepted. The receiver authenticates the exact account,
reviewed role and original task session before resolving its managed database secret
or constructing owners. Owning admission then checks actual ledger/source/packet/job
state before and after operations. Identity authentication is not task liveness or
retirement evidence; managed role trust still needs independent conformance.

Five operations are available: admission, original bootstrap metadata, the existing
Profile-owned principal projection, original completion claim and scalar ready receipt.
Bootstrap requires an uncompleted bound original generation. Completion replay is
immutable, changed clocks are refused, and a completed generation cannot bootstrap
again. Readiness is an authenticated trusted-task assertion after render verification;
this control plane neither renders nor verifies generated bytes. No source objects,
provider grant, reserve, launch, regeneration, renewal, cancellation or death authority
is exposed to a task.

The shared STS signing/verifying and one-attempt Lambda transport preserve existing
cover-letter wire framing. Kind-specific wrappers validate immutable bindings and
replies. Timeout/abort does not release a still-pending original transport or retry it;
owned request/response bytes are cleared after settlement. Proofs remain ephemeral
private transport and never reach owners, persistence, logs or replies. Malformed proof
headers are refused before AWS/owner access.

The new private Lambda source uses independent `NATIVE_RESUME_OWNER_RPC_ENABLED`
and `NATIVE_RESUME_OWNER_RPC_DEPLOYMENT_JSON`, qualified runtime identity and a managed
secret. It refuses ambient database/provider credentials and warm configuration drift.
Documents owns a bounded one-connection control pool with actual same-transaction
Applications/Jobs ports. Profile supplies the original principal through its owner API.
A separate deterministic builder creates `native-resume-owner-rpc-lambda` locally;
publication/IAM/task image/routing and activation are outside this change.
